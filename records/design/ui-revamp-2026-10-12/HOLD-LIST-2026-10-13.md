**Conventions.**

- **N1 to N31** are the rows of CORE-TASK-PROMPT §2 in table order (§1 below).
- **G1 to G5** are the groups of CORE-TASK-PROMPT §8 "Order of work": G1 P0 items (N20, N23, N24, N26); G2 N30; G3
  defects (N1, N2, N8, N10, N13, N15, N16, N18, N19, N22); G4 Kind 1 reads and wiring (N3 to N7, N9, N11, N12, N14,
  N17, N21, N29, N31); G5 N25, N27, N28.
- **Release.** No row has a seam version number yet. The Core lane makes one commit per item and reports at each item
  boundary; the orchestrator records the seam version (CORE-TASK-PROMPT §6, §8). "Release: N24" means "the seam version
  that serves row N24, integrated on main and merged into the lane".
- **N4 is cross-cutting.** Command identity and accepted time are adopted once in the shared receipt helper plus one
  data field per expectation table (seam item S-08; WP-07-design §3.1). A unit whose only Core link is N4 is classified
  **BUILD**.
- **Classifications.** BUILD: no Core row changes what the unit renders or posts. BUILD (pure addition): a Core row adds
  a fact, a state, a refusal code or a sentence; the unit is built now with its designed interim, and the adoption step
  is named. HOLD: a Core row changes the input the unit posts, or the rule its offers or flow mirror; the releasing row
  is named. COMMIT AS IS / REWORK BEFORE COMMIT: for done units.
- **SW (same window).** An adoption step marked SW MUST land in the integration window of its Core row, because an
  interim sentence or a form becomes false or refused when the row lands. Section 3.4 lists them.

### 0.2 Conventions

- **Personas.** Operator: `operator-1` (the assigned operator of every proof application), `operator-2` (the new
  operator after the reassignment of §3 V10-5; isolation), `operator-3` (holds a group read grant; read-only
  checks). They stand for `syn-operator-1` to `syn-operator-3`. SuperAdmin: `superadmin-1` (records payments and
  decisions, requests increases, lowers), `superadmin-2` (the second, distinct SuperAdmin: approves and declines).
  The seed holds two SuperAdmins (`src/modules/identity/commands/seed.ts`); no step needs a third. TA: `syn-ta-1`
  (applications at the default ₹0 ceiling), `syn-ta-3` (applications under a ceiling that two SuperAdmins set),
  `syn-ta-2` (isolation only). Keyboard-only user. Screen-reader user. Phone user (390 px wide). No step suspends a
  seeded account; an inactive requester or operator is a test fixture.
- **Where.** `L`: a person or the LD-11 harness shows it on `lane-ui`. `T`: an automated test in the lane repository
  shows it at the same commit; the run record names the test. `L+T`: both are required. A test that the item says
  WP-07 adds is named in the run record with its file and title.
- **Sign-in codes (rule C).** As WP-01 §0.2. The LD-11 harness signs in. Nobody prints, logs, screenshots or stores a
  code or an authenticator key.
- **Copy.** Quoted text is draft copy (CR-09). Draft copy passes when the page states the same facts. The §11.3
  boundary sentence form is mandatory for an unavailable action: "[Action] is unavailable until [policy or evidence]
  is [approved / recorded]. Owner: [owner or 'not yet named']." Core's reasons show in words; a code shows only as
  the UAT-13 fallback (A115).
- **Money.** Amounts show in rupees ("₹3,500" for 350000 paise; paise only when not zero). The operator and the
  SuperAdmin type rupees. Counted exposure, reservations and fees are separate facts and are never added into one
  figure except where Core returns the sum ("Counted exposure").
- **Dates and times.** Every time carries "IST" (AD-10, CR-06).
- **Freshness (LD-08).** An authoritative read (`core.*`, `ops.*`, `pay.*`) shows "Read at [time] IST". A projection
  (`views.*`) shows "Up to date when read at [time] IST", "Behind by [n] s when read at [time] IST" or "Freshness
  unavailable". No page applies a client-side age threshold.
- **Facts.** A page shows only facts that a read returns (WP-02 B-06). A fact read after an operation is labelled
  "Current". A count that a read cannot give shows "Unavailable", never "0" (D7). A list that returns its row limit
  says so and claims no total. The operator reads return no service payment status, no Gate 1 or Gate 2 state field,
  no exposure figure and no ceiling (Q-11): an operator page shows Core's evaluation of the next action instead.
- **Control words.** Readiness validity: "Not recorded", "Recorded by [you / name], [time] IST", "On hold",
  "Out of date", "Recorded by the previous operator". Act state: "Not authorized", "Authorized: not yet evidenced",
  "Filed (evidence recorded)", "Not executed (evidence recorded)", "Execution uncertain", "Reconciliation exhausted".
  Gate exception: "Open until [time] IST", "Used", "Revoked", "Expired". An exception row reads "Action allowed by
  exception: [gate], for [action], once", never "Payment received". A control with no exception reads "No exception
  exists for this control." Gate 2 on SuperAdmin pages, as `pay.application_payments.gate2` reports it: "Passed",
  "Passed by exception", "Blocked", "Not applicable", "Unavailable" (Q-03).
- **Receipts.** CMP-08 as WP06-A103: the request reference links to the operation status page; the resulting facts;
  "Recorded once. Sending the same form again does not repeat it."; no accepted time (P-02). A receipt names the
  command only when the operation's resource, the returned id and the summary establish it, or when a read by the
  returned id establishes it (the step code of a step id; the kind of a ceiling change; the id prefix of a hold).
  Otherwise the receipt reads "Request recorded" with the current facts labelled "Current" (WP-06 D-02). The polite
  region announces it.
- **Replay terms** (used by every "Nth time" item; the five terms of the lane):
  1. *Identical replay*: the harness sends the accepted request again with the same `_op` and the same fields (raw
     envelope); a double-click on the final button is the same case. Expected: the original result, nothing new
     recorded, no second external effect.
  2. *Changed-content conflict*: the harness sends the same `_op` with one changed field. Expected: refused as a used
     form (`conflict_operation_key`); the page re-renders with a new form key, the typed values kept and "This form
     was already used with different content. Your values are kept: check them and send again."; nothing recorded.
  3. *Browser Back*: after the receipt the person presses Back. Back reloads the page (WP-01 A-02) with a fresh form
     and current facts. A send from that page is a new request; the command's own business check decides it.
  4. *Rejected-form refresh*: a send that Core refuses leaves no operation record; the re-rendered form carries a new
     key; the corrected send is recorded once.
  5. *Lost acknowledgement* (fixture): C4 (CMP-13) "Checking the original result" and "Check status"; no new send of
     the same intent is offered there. For an authorization the text is "Authorization result unknown. Do not
     perform the external act."
  Two more cases belong to the replay matrix (A113), never to a term: a *business duplicate* (a new key with
  the current page's facts) and a *raw stale envelope* (a new key with an older page's revision).
- **Refused sends leave no record.** A refused command leaves no operation record: the status page of its key reads
  "Nothing is recorded for request [reference] so far", and the refusal shows only on the re-rendered form. Every
  refusal item below says "nothing is recorded" and checks it by delta where a list or a figure could change.
- **Paths (LD-03).** Existing paths and form actions stay. New pages get new paths that the design names. Pages:
  OP-01 `/ops/work` (existing; views in the address); OP-02 `/ops/applications/:applicationId` (existing; tab in the
  address); OP-03 return and flag pages (new paths; actions `/ops/applications/:applicationId/return` and `/flag`
  stay); OP-04 review, evidence and reconciliation pages (new paths; actions `/ops/applications/:applicationId/acts`,
  `…/acts/:authorizationId/evidence` and `…/reconciliation` stay); the operator case-work actions `start-work`,
  `work-steps`, `effort-samples`, `readiness`, `readiness/:readinessId/withdraw` stay; SA-07f `/admin/finance` and
  SA-07t `/admin/finance/tas/:taAccountId` (existing; actions `…/ceiling/lower` and `…/ceiling/increase-request`
  stay); SA-09c `/admin/finance/ceiling-changes/:changeId/decide/:kind` (new, `approve` or `decline`; actions
  `…/approve` and `…/decline` stay); SA-09 Gate 2 `/admin/applications/:applicationId/decide/gate2_commitment` (new;
  action `/admin/applications/:applicationId/gate-exceptions` stays); SA-09r of WP-06 for the revocation; SA-07a
  `/admin/applications/:applicationId/payments` (WP-06). An item names the page; the run record names the path used.
- **Pass rule.** WP-07 passes when every `L` item passes on `lane-ui` at the integrated ref, every `T` item has a
  named passing test at that commit, every axe item passes, and the proofs V08, V09 and V10 (section 3) pass, except
  the explicitly deferred items of §5. The run record lists each deferred item as "Deferred" with its reference, not
  as "Fail". An item that the architect marks "partly met" by a recorded decision passes with that note. A failed item
  becomes a finding ranked P0, P1 or P2 with its scenario (PRI-20260930-01).
- **Preconditions on `lane-ui`.** WP-01, WP-02, WP-03 and WP-06 are integrated (TA pages create, edit, submit,
  report a problem and hand back; SA-07a records payments; SA-03 assigns and reassigns; SA-09g records Gate 1
  exceptions; the carried WP-09 forms answer a flag and resolve holds). The installation holds the synthetic seed of
  WP-02 §0.3. `syn-ta-1`'s ceiling is the default ₹0 (never set); the V08-0 baseline records it. The harness holds the
  synthetic sample documents of WP-03 §0.4.
- **Data hygiene.** WP-07 MUST NOT change seeded offerings, launches or listings, and MUST NOT suspend or edit a
  seeded account. It creates its own groups and applications per run through the TA pages, with references, notes
  and reasons that carry the run stamp. Counted exposure never decreases (BS B28): each run adds the reservations of
  §0.4 to `syn-ta-1` and `syn-ta-3` for good. The run sets and lowers the ceiling of `syn-ta-3` only, and never sets a
  ceiling for `syn-ta-1` (its default ₹0 is the subject of A60) or `syn-ta-2` (Q-07). No real bank
  reference, portal reference, person or passport is used. The run record keeps identifiers (applications,
  authorizations, reservations, changes, exceptions, operation references) in the internal record only.

### 0.4 Run recipe (rerunnable)

- Stamp `[yyyymmddhhmm]` (the run tag). Data of earlier runs stays and is excluded by its stamp. Every check compares with the
  baseline of §3 V08-0 or V09-0 (deltas), never with totals.
- Setup (TA pages of WP-03, the harness signed in as the travel agent): group `wp07-g1-[stamp]` of `syn-ta-1` in
  Synthetica, travel start today + 30 days, return today + 40 days, with applicants P and U ("SYN Tourist e-visa"),
  Q ("SYN Tourist visa preparation") and H ("SYN Tourist visa via provider"); group `wp07-g3-[stamp]` of `syn-ta-3`
  with R, N and M ("SYN Tourist e-visa"). Synthetic passports and photographs are generated in memory (WP-03 §8.1).
  All seven are submitted on TA-08.
- Setup (SA pages of WP-06, `superadmin-1`): record "Payment received" for P, Q, H, R and M on SA-07a; record a Gate 1
  exception for assignment for U and N on SA-09g; assign all seven to `operator-1` on SA-03a; record a Gate 1
  exception for the first operator work for N on SA-09g (U's is part of V08).
- Setup (existing grant page, `superadmin-1`): a group read grant of `wp07-g1-[stamp]` for `operator-3`, purpose and
  end date with the stamp.
- Ceiling numbers for `syn-ta-3`, from the V09-0 baseline (current ceiling C0, counted exposure E0): the requested
  ceiling C1 = max(C0, E0) + ₹2,500; R and N each commit ₹1,000; M first commits the headroom read just before plus
  ₹100 (a breach); after the lowering to (counted exposure − ₹500), M commits ₹100 (a breach again).
- Gate exceptions expire after Core's lifetime (the page never states it). The run reaches V09-6 within that
  lifetime of the set-up, or records the exceptions of U and N again as set-up.
- At the end of a run `syn-ta-3`'s ceiling is lower than its counted exposure, no increase request is open, and
  every act of the run is evidenced or uncertain as the steps leave it. The next run starts from those values.

## 5. Out of scope and boundaries

These MUST NOT appear on any WP-07 page:

- An authorization, act evidence or reconciliation by anyone other than the current assigned operator; a SuperAdmin
  readiness, filing, packet, send or completion control (BS B18, B23).
- A label that turns authorization into execution ("File visa", "Filed" before evidence) or uncertainty into failure
  ("Not filed" from elapsed time) (BS B23; UX §5.3).
- A repeat authorization, fee act or ordinary withdrawal offered while a filing or a fee payment may have happened
  (BS B23).
- An exception, override or decision route for the exposure ceiling, a mandatory validation or a fixed cut-off; one
  "Override" for every blocker (BS B20, B28; UX §6.3).
- A Gate 1 exception presented as passing Gate 2; a Gate 2 decision presented as a payment, as readiness or as an
  authorization of the act (BS B20, B27).
- A ceiling increase that takes effect without a second, distinct SuperAdmin; a control that lowers counted exposure,
  releases a reservation, excludes a fee, writes off, refunds or records a receipt allocation (BS B28, B29, B43).
- A blanket "TravelMudra-funded commitments are blocked" message instead of the specific B28 case (BS B43).
- A page-side computation of permission, Gate 2, exposure headroom as a permission, or view membership outside the
  closed mapping table (PL §6; BS B33, B35).
- A count shown as "0" when it is unknown; a list that hides its row limit; an age, deadline or travel-risk mark that
  no read returns (D7; CR-03).
- Earlier facts on a page after an optional read was refused for access (LD-14).
- A receipt that names a result the operation does not establish, or an accepted time (C-03; P-02).

Deferred in WP-07 (each item says where it lands; the run record lists them as "Deferred"):

- Pre-send display of the exposure check, the ceiling and the parked paid case on OP-04: no operator read returns
  them; the refusal after the send shows them (Q-11).
- Gate 2 state on SuperAdmin pages while `pay.application_payments.gate2` answers `unknown` (Q-03): the row and the
  evidence read "Unavailable" and Core decides at send.
- The read-only section of OP-01 while `views.ops_work` refuses operators (Q-02): "Unavailable".
- A SuperAdmin queue entry for "Gate 2 decision needed" (Q-01): the interim route is the operator's flag.
- "Continuing duties" for completed applications with a financial follow-up (Q-08); country in the identity band
  (Q-09); the control kind of each blocker from Core (Q-10, the page maps codes); recorded effort samples (Q-16).
- Evidence references on the Gate 2 decision (P-11, S-07): "Unmet — waits for P-11".
- The accepted time in receipts (P-02); receipt facts that the P-10 batch serves later (S-08).
- Readiness-gate exception kinds on SA-09 (Q-13): the carried generic form keeps the readiness values.

Not in WP-07 (later packages):

- OP-05 to OP-10 (WP-08, WP-14, WP-12, WP-15); send result and completion stay boundaries (LD-04).
- Packet build, release and handover; provider filing evidence (WP-10).
- Reconciliation exhausted and the SuperAdmin's unresolved external outcome (WP-11).
- Approved-help entry, "Return for TA review", flag response, resolve hold (WP-09; carried forms).
- Deferral, withdrawal, forecast, travel-date recheck (WP-17; carried forms).
- Government fee facts entered by a SuperAdmin, follow-up list and owner reassignment, refund, write-off, fee
  exclusion and reservation release as decisions (WP-16; no command exists for the fee facts at 42cb373).

## 4. Reviews

### 4.1 Independent design review (Codex gpt-6.1-sol, high effort, read-only, 13 October 2026)

Full text: lane `research/reviews/WP-17-design-review.md`. 13 findings: 1 P0, 12 P1. One review, no follow-up (LD-13).
Reviewed against product b2a6341. Confirmed sound: closure checks all open applications and intake blockers; group end
excludes possible filing, held or uncertain originals, pending email and outstanding money; withdrawal assessments keep
recorded refusals apart from outcomes; outcomes supersede open price increases; paid amounts stay separate; forecasts keep
the original estimate; an approved deferral blocks readiness; CC-21, LD-14, whole-input parsing and neutral receipts.
Amendments bind the implementation and govern where they differ from `WP-17-design.md`.

| Finding | Rank | Disposition (amendment) |
|---|---|---|
| R-01 the past-date safeguard is absent from the executable design; A11 contradicts it | **P0** | **O-01.** Worked now as a class fix in the already-built travel-dates page (TA-13b, WP-03 fixes): a browser minimum; past dates send nothing until a BFF-only acknowledgement equal to the exact submitted dates is given after a review that states what the next date check ends; tests for missing acknowledgement, changed dates, stale revision, replay and future dates. The WP-17 design and A11, V19-2 follow. Refusing past dates in Core changes accepted command behaviour: a Kind 2 assessment in P-21 for Max. |
| R-02 the price acceptance uses the wrong unit | P1 | **O-02.** Acceptance uses paise (`400000` for ₹4,000); over-limit input refused whole; the proposed amount is shown converted to rupees in the review before the send. |
| R-03 "Keep the quoted price" can name the wrong price | P1 | **O-03.** "Decline the increase; keep the current price ₹[current effective price]"; the original quote labelled separately; a fixture with a catalogue reduction between proposal and decision. |
| R-04 the held-correction review promises unavailable evidence | P1 | **O-04.** The page says the held values are not available on this page; `held_correction_conflict` (category stale) routes to the conflict explanation; "cannot be applied to the current details"; readable values stay an acceptance gap pending the criterion exception (P-21). |
| R-05 ended-deferral pages need facts the read cannot return | P1 | **O-05.** GET with no open deferral: "No deferral is currently open" (no invented history); verified receipts and POST refusal rendering kept apart; no early absence check that blocks replay reconciliation; a subject read requested only if exact history is required (P2 note). |
| R-06 deferral copy implies automatic release | P1 | **O-06.** Everywhere (banners, notices, queues, checklist words, WP-06 D-23, WP-07 F-39, WP-08 E-30): "Review on [date]; readiness, authorization and packet release remain held until the deferral is ended." |
| R-07 timing notices described as acknowledgement-required | P1 | **O-07.** No acknowledgement promise for `timing_risk`; acceptance asserts the recorded flag. |
| R-08 receipts claim unsupported commands | P1 | **O-08.** "Request recorded" for the shared deferral summary and for unchecked receipts; tests with proposal and end keys at the decision receipt address and with another actor's key. |
| R-09 end-deferral body limit | P1 | **O-09.** OP-02e is in the body-limit table, sized for its complete encoded envelope; a real HTTP maximum-input test. |
| R-10 saved-envelope tests expect later guards before revision checks | P1 | **O-10.** Unchanged-envelope stale tests are separate from fresh-revision duplicate tests (A18, A51, W-2, D-2). |
| R-11 acceptance contradicts hosts and state handling | P1 | **O-11.** The Product Manager aligns A01, A13 (the return link on TA-07w, G-12), A33, A66, A69 (deferral decisions carry no expected revision; competing extensions can both succeed). |
| R-12 V19 can pass without its defining exclusions | P1 | **O-12.** One recipe; isolated fixtures for each exclusion (possible filing, held originals, pending delivery, outstanding money) with UI assertions; the general deferred-item exception does not waive them; the intake test title corrected to its assertion. |
| R-13 "defect" does not settle the classification | P1 | **O-13.** P-21 splits behaviour proposals (refusing past-date edits, refusing post-outcome deferrals, ending deferrals automatically: Kind 2 assessments for Max) from surface repairs. An admin end-deferral surface needs no Core change (policy, binding and staff allowlist exist): WP-17 builds it on SA-04a. Forecast basis and held values stay criterion-exception requests. |

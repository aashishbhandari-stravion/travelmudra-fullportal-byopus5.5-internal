## 4. Reviews

### 4.1 Independent design review (Codex gpt-6.1-sol, high effort, read-only, 13 October 2026)

Full text: lane `research/reviews/WP-09-design-review.md`. 11 findings: 11 P1, no P0. One review, no follow-up (LD-13).
Reviewed against product e9e96e3. The reviewer confirmed: the report eligibility facts match Core (including approved
assistance and after an outcome); the entry's command scope; unchanged identity values need no evidence; the
deterministic mapping fixes replay drift; the entry form and Core's first-work evaluation use the same gate and action
(`start_operator_work`, recorded assignment basis), so the condition of Q-W09-07 is met; formal return is the right
ending; F-13 is sound. Amendments bind the implementation and govern where they differ from `WP-09-design.md`.

| Finding | Rank | Disposition (amendment) |
|---|---|---|
| R-01 a resolved hold does not establish the receipt's command | P1 | **G-01.** The `resolved` receipt is neutral ("Request recorded") with the current hold facts labelled "Current" until command identity is served (S-08; class of WP-06 D-02). Test: open the flag operation's key at the resolve receipt address after the flag was resolved. |
| R-02 exhausted reconciliation described as a held entry | P1 | **G-02.** OP-02a separates two states: execution authorized or unknown (an entry can be held) and reconciliation exhausted (Core refuses the entry with `filing_possibly_occurred`; no form; the reason and its owner). Copy test for each. |
| R-03 new-key duplicate expectation false for held entries | P1 | **G-03.** "Nothing changed" is expected only for an applied entry. A repeated proposal with a new key while the first is held records another held correction; OP-02a shows the held entries it can read before the form, so the operator sees one is waiting. No semantic duplicate guard is claimed; a Core guard would be a behaviour proposal (P2 note, not raised). |
| R-04 checklist requires the superseded help-decision model | P1 | **G-04.** The Product Manager aligns: two kind pages with a fixed hidden `decision`, reason validation; obsolete or foreign request ids tested through POST envelopes (stale refusal, unsent reason kept), not a historical GET. |
| R-05 live Gate 1 proof requires the removed form | P1 | **G-05.** The Product Manager aligns: on GET, assert the blocker, no entry or upload form, and the "Return for TA review" link kept; command refusal tested with a saved envelope in a test; an unavailable evaluation keeps the form and Core decides. |
| R-06 checklist tells a submitted case to submit | P1 | **G-06.** The Product Manager splits A50 and V07-D5 by lifecycle (WP-07 F-14): a submitted case asserts hand back, unchanged quote and original window, same operator, readiness confirmed again; adds return without any entry. |
| R-07 refusal discards selected identity evidence | P1 | **G-07.** Evidence selections start unchecked on a fresh form and are restored from the posted values after a refusal (input kept, UX §3.3); an over-limit selection stays visible with its field error; nothing is truncated. Confirmations and attestations stay unchecked after a refusal (WP-03 rule) — evidence selection is not a confirmation. |
| R-08 assigned approval row inherits contradictory effects | P1 | **G-08.** The SA-09h effect row for an assigned application is written in full: entry starts at once and the travel agent cannot edit; Core checks Gate 1 for the first work and may consume a first-work exception, opening a payment follow-up owned by its grantor; an open return closes. No unassigned-only sentence is inherited. |
| R-09 checklist omits reassignment races | P1 | **G-09.** The Product Manager adds: a stale help approval across a reassignment; a flag response after OP1 → OP2 (raiser and current operator named separately; notice to OP2; OP2 resolves; OP1 refused by access). |
| R-10 replayed response receipt says a resolved flag is open | P1 | **G-10.** The `responded` receipt keeps the historical response and derives the current flag line from the returned hold's current state. Tests: revisit after resolution and after a newer flag opens. |
| R-11 parked STOP notes do not establish Kind 1 | P1 | **G-11.** STOP-W09-02 to -04 stay parked (P2) with "criterion point 2 not demonstrated" recorded; the travel-agent scope of STOP-W09-03 needs its own justification before any proposal. No proposal is raised now. |
